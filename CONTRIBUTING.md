# Contributing to Qwiic_Py

Thanks for helping! Qwiic_Py holds every SparkFun Qwiic Python driver in one repository. Each driver is still a separate package on PyPI, mip and the CircuitPython bundle, so users install only the drivers they need.

Bugs and feature requests go in [the issue tracker](https://github.com/sparkfun/Qwiic_Py/issues). Pull requests are welcome; the checks below run on every one.

## Repository layout

```text
Qwiic_Py/
├── qwiic_i2c/                the bus layer every driver uses
├── drivers/
│   └── qwiic_<chip>/         one directory per device driver (layout below)
├── qwiic/                    sparkfun-qwiic meta-package (generated registry)
├── tools/                    generators and checks used by CI
├── tests/                    unit and smoke tests (no hardware needed)
└── docs/                     Read the Docs landing page and shared Doxygen config
```

Each driver directory:

```text
drivers/qwiic_<chip>/
├── pyproject.toml            the only place name, version and dependencies are written
├── package.json              mip manifest, generated by tools/gen_package_json.py
├── qwiic_<chip>.py           one module (a package only when there are data files)
├── examples/
│   ├── qwiic_<chip>_ex<N>_<description>.py
│   ├── package.json          examples mip manifest, generated
│   └── README.md             one section per example
├── docs/images/              README images
├── README.md                 standard sections, see drivers/qwiic_bme280/README.md
└── LICENSE                   MIT
```

## Driver conventions

These are checked by `tools/check_driver.py`.

1. **Class:** PascalCase `Qwiic<PART>`, with the part number as printed on the product (`QwiicBME280`, `QwiicICM20948`). PEP 8 keeps acronyms in capitals.
2. **Class attributes:** `device_name` (from `_DEFAULT_NAME = "Qwiic <Part>"`) and `available_addresses` (from `_AVAILABLE_I2C_ADDRESS`, default address first) on every driver class.
3. **Module version:** `__version__` equal to the `pyproject.toml` version, in every module listed in `py-modules` (circup reads each one's version separately), or in the package's `__init__.py`. `tools/bump_version.py` updates them all.
4. **Constructor and lifecycle:** `__init__(self, address=None, i2c_bus=None)`, starting with `address, i2c_bus = qwiic_i2c.device_args(address, i2c_bus)` (so the bus may come first: `QwiicBME280(bus)`, `QwiicBME280(bus, 0x76)`) and then `self._i2c = qwiic_i2c.get_i2c_bus(i2c_bus)`, which also accepts a native bus object; `is_connected()`; `begin()` returning `True` only if every check passed, otherwise `False`.
5. **Names:** PEP 8 throughout: `snake_case` methods, functions, arguments and variables; `PascalCase` classes; `UPPER_CASE` constants; lowercase module names. One name per method: no camelCase twins or aliases.
6. **No `property()`:** use plain methods (`get_<x>()`, `set_<x>(value)`, `read_<x>()`, `is_<x>()`). Some MicroPython builds don't have `property()`.
7. **I2C:** call the `qwiic_i2c` 3.0 methods (`read_block`, `write_block`, `read_byte`, `write_byte`, `read_word`, `write_word`) on `self._i2c`, always passing the device address. Pass a register wider than 8 bits as its bytes (`[reg >> 8, reg & 0xFF]`); use `byteorder="big"` for big-endian words.
8. **Delays and timeouts:** `self._i2c.delay_ms()`, `delay_us()`, `ticks_ms()` and `ticks_diff()`. Never import `time`: some platforms have none, and the others disagree on what it offers. Always compare ticks with `ticks_diff()`, never by subtracting.
9. **No side effects:** no `print()` and no bare `except:` in drivers. Return values, or raise `OSError` / `ValueError`.
10. **Portable subset:** standard library limited to `struct`, `math` (basic functions; use `math.log(x) / math.log(10)` rather than `math.log10`), `sys` and `micropython.const` with a CPython fallback. No `os`, `typing`, `enum`, `dataclasses`, `subprocess`, `from __future__` or relative imports. Drivers that genuinely need Linux (serial, SPI) say so with `[tool.qwiic] platforms = ["cpython"]`.
11. **Single module:** one flat module per driver. A package (`qwiic_<chip>/`) only when the driver ships data files, such as fonts or firmware.
12. **Examples:** examples are plain scripts that read top to bottom: no `run_example()` function and no `if __name__ == "__main__"` guard, so they can be pasted into a REPL or saved as `code.py`/`main.py`. When the device isn't found they print a message and call `sys.exit(1)`. They use only the public API, wait with `qwiic_i2c.delay_ms()`, and are named `qwiic_<chip>_ex<N>_<description>.py`. Most should run unchanged on CPython, MicroPython and CircuitPython. An example may need one platform (for example `RPi.GPIO` on a Raspberry Pi HAT, or matplotlib for plotting) if its header comment and `examples/README.md` say so. The driver itself must still run on every platform.

## Tools

Run them from the repository root with Python 3.9 or later:

| Command | What it does |
| --- | --- |
| `python tools/make_pyproject.py <driver> --dist-name <pypi-name> --description "..."` | Writes the standard `pyproject.toml` |
| `python tools/bump_version.py <package> <X.Y.Z \| major \| minor \| patch>` | Sets a package's version and regenerates every file that copies it |
| `python tools/gen_package_json.py [driver ...]` | Regenerates `package.json` and `examples/package.json` |
| `python tools/check_driver.py [driver ...]` | Checks the conventions above; needs `pip install mpy-cross` for the compile check |
| `python -m unittest discover -s tests` | Unit tests for qwiic_i2c and a smoke test of every driver |
| `micropython tests/micropython_smoke.py` | The same smoke test on MicroPython's Unix port |
| `python tools/gen_registry.py` | Regenerates the `qwiic` meta-package registry and dependency list |
| `python tools/gen_migration.py` | Regenerates `MIGRATION.md` from each driver README's "Migrating from 2.x" section |
| `python tools/build_bundle.py` | Builds the CircuitPython bundle zips |
| `python tools/build_docs.py [--strict]` | Builds every driver's Doxygen API reference into `site/` (needs doxygen); `--strict` fails on any Doxygen warning, as CI does |
| `python tools/make_forwarding_stubs.py` | Writes the final README and package.json for each old per-driver repository |

## Adding a driver

1. Copy `drivers/qwiic_bme280` as a starting point and rename it.
2. Write the driver and at least one example following the conventions.
3. Run `tools/make_pyproject.py`, `tools/gen_package_json.py`, `tools/gen_registry.py` and `tools/gen_migration.py`, then `tools/check_driver.py <driver>` and the tests until they pass.
4. Open a pull request.

## Releases

Each package (every driver, `qwiic_i2c` and the `qwiic` meta-package) has its own version and is released on its own:

1. Run `python tools/bump_version.py qwiic_bme280 patch` (or `minor`, `major`, or an exact `X.Y.Z`). It sets `version` in `pyproject.toml` and `__version__` in the module, then regenerates:
    - the mip manifests
    - the meta-package's dependency list
    - `docs/drivers.md`
2. Open a pull request with the changes and merge it.
3. Tag main as `<package>-<version>` (for example `qwiic_bme280-3.0.1`) and push the tag. CI publishes that package to PyPI.

Push the tag as soon as the pull request merges. Drivers' mip manifests pin their dependencies to release tags, so after a `qwiic_i2c` release, every driver's manifest points to the new tag.

A major version is outside the `<N` range in other drivers' requirements. `bump_version.py` lists those drivers, so you can update their requirements and test them.

The changes reach users at different times:
- **mip:** installs from main, so mip users get the change when the pull request merges.
- **pip:** when the tag is pushed.
- **CircuitPython:** with the next bundle release. Those are separate GitHub Releases, named by date.

## Converting a 2.x driver to v3

1. **Module:**
    - Add `__version__ = "3.0.0"`.
    - Rename the class per convention 1.
    - Start the constructor with `address, i2c_bus = qwiic_i2c.device_args(address, i2c_bus)`, then `self._i2c = qwiic_i2c.get_i2c_bus(i2c_bus)`.
    - Replace the 2.x qwiic_i2c names (`readByte` → `read_byte`, `isDeviceConnected` → `is_device_connected`, ...).
    - Replace `time.sleep(s)` with `self._i2c.delay_ms(ms)`, and any timer with `ticks_ms()` and `ticks_diff()`.
2. **Remove `property()`:**
    - A property backed by a method becomes that method.
    - A property with no method gets a `get_`, `set_` or `read_` method.
    - Update internal uses (`self.pressure` → `self.read_pressure()`).
3. **Names:** rename camelCase methods and arguments to snake_case, and delete duplicates and aliases. Fix typos in public names while the API is breaking anyway.
4. **Cleanup:** remove `print()` and bare `except:`, and make `begin()` return a real result.
5. **Examples:**
    - Rename them per convention 12.
    - Update them to the new API.
    - Replace `import time` with `qwiic_i2c` delays.
    - Make them plain scripts: move the body of `run_example()` to the top level and remove the `__main__` guard.
    - Rewrite `examples/README.md` with the new file and method names. Don't use Doxygen deep links, because their anchors change with every build.
6. **Packaging:** run `tools/make_pyproject.py` with the driver's existing PyPI name, then `tools/gen_package_json.py`. Delete `setup.py`, `setup.cfg` and `requirements.txt`.
7. **README:** follow `drivers/qwiic_bme280/README.md`: v3 install commands, the quickstart updated to the new API, and a **Migrating from 2.x** table listing every renamed or removed public name.
8. Run `tools/check_driver.py <driver>` and the tests until both pass.
