# Migrating from Qwiic_Py 2.x to 3.0

Version 3 gives every driver the same conventions (see [CONTRIBUTING.md](CONTRIBUTING.md)):

* **One name per method, PEP 8 style.** camelCase methods and duplicate aliases are gone, classes use the part number in capitals (`QwiicBME280`), and constants are `UPPER_CASE`.
* **No properties.** `sensor.connected` is `sensor.is_connected()`; every other property is replaced by its `get_`/`set_`/`read_` method.
* **No `print()` and no `time` module in drivers.** Errors are return values or exceptions; delays go through `qwiic_i2c` (`delay_ms`, `ticks_ms`, ...).
* **The bus can be the first argument.** `QwiicBME280(machine.I2C(1))` and `QwiicBME280(bus, 0x76)` work in every driver, as well as `i2c_bus=bus`, which replaces the 2.x `i2c_driver=` keyword. The bus can be the platform's own object (`machine.I2C`, `busio.I2C`, `smbus2.SMBus`). Code that passes the address first, or the bus positionally, is unchanged.
* **New install paths for MicroPython.** `mpremote mip install github:sparkfun/Qwiic_Py/drivers/<driver>` instead of `github:sparkfun/<old repo>`. PyPI names don't change.
* **`qwiic_i2c` 3.0.** See [its migration table](qwiic_i2c/README.md#migrating-from-2x). Most programs only notice `getI2CDriver()` becoming `get_i2c_bus()`.

Version 2 remains on PyPI (pin `<3`) for Python 3.6 and 3.7 users.

This page is generated by `tools/gen_migration.py` from each driver's README. The changes per driver:

## qwiic_i2c

Version 3 keeps one name per method. The camelCase twins are gone, and the bus object is called a bus rather than a driver, so it isn't confused with the device drivers.

| 2.x | 3.0 |
| --- | --- |
| `getI2CDriver()`, `get_i2c_driver()` | `get_i2c_bus()` |
| `I2CDriver` (base class) | `I2CBus` |
| `i2c_driver=` argument of every device driver | `i2c_bus=` (or pass the bus first) |
| `isDeviceConnected()`, `ping()` | `is_device_connected()` |
| `readByte`, `readWord`, `readBlock` | `read_byte`, `read_word`, `read_block` |
| `writeByte`, `writeWord`, `writeBlock` | `write_byte`, `write_word`, `write_block` |
| `writeCommand(address, command)` | `write_byte(address, None, command)` |
| `writeReadBlock(address, [reg_hi, reg_lo], n)` | `read_block(address, [reg_hi, reg_lo], n)` |
| `readWord`/`writeWord` were little-endian only | `byteorder="big"` for high byte first |
| `isPlatform()` | `is_platform()` |
| `driver.i2cbus` | `bus.native_bus` |
| `LinuxI2C(iBus=n)` (ignored `n`) | `LinuxI2C(bus_id=n)` |
| `get_i2c_driver()` returned `None` on an unsupported platform | raises `RuntimeError` |
| `qwiic_i2c` package (`qwiic_i2c/__init__.py`, ...) | flat modules `qwiic_i2c.py` + `qwiic_i2c_<platform>.py` |
| The default bus on RP2 and ESP32 ran at 400 kHz, ignoring the 100 kHz default (too fast for some ATtiny-based boards) | It runs at 100 kHz, or the `freq=` you pass |

Version 3 has no `debug` option and never prints, and the constructor no longer talks to the board: call `begin()`.
